1. MODULE OVERVIEW
================================================================================

The 'app' module is the core web application module of Apache Roller. It contains
all the business logic, web interfaces, data access layer, and resources needed
to run the Roller blogging platform.

Purpose:
- Implements the complete web-based blogging application
- Provides REST and web services for blog management
- Handles user authentication and authorization
- Manages blog content, comments, and media files
- Renders blog themes using Velocity templates
- Provides administrative interfaces

Output Artifact:
- roller.war: Deployable web application archive
- Can be deployed to Apache Tomcat, Jetty, or other servlet containers

4. KEY COMPONENTS
================================================================================

4.1 Business Layer (org.apache.roller.weblogger.business)

Key Classes and Interfaces:

- AbstractURLStrategy.java     : Base class for URL generation strategies
- BookmarkManager.java         : Manages blogroll bookmarks
- DatabaseProvider.java        : Database vendor abstraction
- FileContentManager.java      : File content storage interface
- FileContentManagerImpl.java  : File content storage implementation
- GuiceWebloggerProvider.java  : Google Guice dependency injection provider
- HitCountQueue.java          : Asynchronous hit counter
- MailProvider.java           : Email service abstraction
- MediaFileManager.java       : Media file management
- MultiWeblogURLStrategy.java : Multiple blog URL strategy
- OAuthManager.java           : OAuth authentication manager
- PreviewURLStrategy.java     : Preview mode URL strategy
- Weblogger.java              : Main facade for business operations

Purpose:
- Implements all core business logic
- Provides service interfaces for web layer
- Manages transactions and data persistence
- Handles system initialization and configuration

4.2 Data Model (POJOs - Plain Old Java Objects)

Location: org.apache.roller.weblogger.pojos

Common POJO Patterns:
- JPA annotations for ORM mapping
- Getters and setters for properties
- Relationships between entities
- Serializable implementation

Key Entity Types:
- User entities (authentication, profiles)
- Weblog entities (blogs, entries, comments)
- Media entities (files, directories)
- Configuration entities (settings, templates)
- Security entities (roles, permissions)

4.3 Web Layer (org.apache.roller.weblogger.ui)

Technology: Apache Struts2 MVC framework

Components:
- Actions: Struts2 action classes for handling requests
- Interceptors: Request/response processing interceptors
- Renderers: Content rendering components
- Validators: Form and input validation

Request Flow:
1. Client request arrives
2. Struts2 filters process request
3. Action class method executed
4. Business logic invoked via managers
5. Result rendered (JSP or JSON)
6. Response sent to client

4.4 Data Access Layer

Technology: JPA (Java Persistence API) with Hibernate

Configuration:
- Location: src/main/resources/META-INF/persistence.xml
- Provider: Hibernate ORM
- Database Support: MySQL, PostgreSQL, Derby, Oracle, DB2, MSSQL, HSQLDB

Features:
- Entity-relationship mapping
- Transaction management
- Query optimization
- Caching strategies
- Connection pooling

11. INITIALIZATION PROCESS
================================================================================

Application Startup Sequence:
1. Servlet container loads web.xml
2. Spring/Guice initializes dependency injection
3. DatabaseProvider initializes connection pool
4. Hibernate validates/updates schema
5. Configuration loaded from properties
6. Managers and services initialized
7. Struts2 framework configured
8. Application ready for requests

First-Time Setup:
1. Access application URL
2. Installer checks for existing database
3. If not found, runs installation wizard
4. User creates admin account
5. Database schema created
6. Default configuration set
7. Application ready for use

15. TROUBLESHOOTING
================================================================================

Common Issues:

1. Database Connection Errors:
   - Check JDBC driver in WEB-INF/lib
   - Verify database connection properties
   - Ensure database is running
   - Check firewall settings

2. Deployment Failures:
   - Verify Java 11+ installed
   - Check server logs for errors
   - Ensure sufficient memory allocated
   - Verify all dependencies present

3. Theme Issues:
   - Clear browser cache
   - Check Velocity template syntax
   - Verify theme configuration
   - Review server logs for errors

4. Performance Problems:
   - Increase JVM heap size
   - Enable database connection pooling
   - Configure caching appropriately
   - Optimize database queries
